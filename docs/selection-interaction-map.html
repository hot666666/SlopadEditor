Primary rule

pointer-down이 의미를 잠근다

드래그 거리는 선택 모드를 바꾸는 신호가 아니다. AppKit은 시작 영역을 분류하고, Session은 mouse-up까지 그 모드를 유지한다. 빈 블록은 텍스트로 칠하지 않지만 논리 범위에서는 빠지지 않는다.

텍스트 laneglyph · line fragment · empty editable blockC → T1 / TN
OR
구조 여백left gutter · left/right structural marginB → B
Canonical vocabulary

다섯 상태 + 하나의 runtime overlay

TN은 새 enum case가 아니다. 기존 TextSelection(anchor, focus)의 두 endpoint가 서로 다른 블록을 가리키는 형태다.

I

Inactive

caret도 selection도 없음

C

Caret

한 TextPosition · focused면 native blink

T1

Single-block text

같은 블록 안의 비어 있지 않은 범위

TN

Cross-block text

서로 다른 블록의 anchor / focus

B

Block selection

명시적인 구조 단위 선택

MComposition은 여섯 번째 selection mode가 아니다. callback마다 실제 편집 내용을 갱신하는 것은 결정된 미래 목표다. 현재 구현은 Session overlay를 commit 때 canonical content에 적용하며, 설치된 IME 입력은 아직 이 consumer에 도달하지 않는다.

High-level UI contract

UI가 selection policy를 다시 만들지 않게

toolbar·context menu·link editor·clipboard·accessibility는 같은 selection을 서로 다른 비용으로 본다. canonical, command-time, viewport presentation을 분리한다.

Evidence boundary

확인한 것과 확인하지 못한 것

Notion Playground에서 직접 확인

  • Escape: caret/T1/TN → 걸친 블록 선택, B → inactive
  • Cmd-A: 현재 text scope 확장 후 전체 block 선택; empty caret은 즉시 전체 block
  • Shift+방향키의 separator-only 경계 step과 역방향 anchor/focus
  • 빈 중간 블록은 text rect 없음, Escape/delete/structured payload에는 포함
  • cross-block delete/paste merge, inline formatting, copy/cut payload 구분
  • 삭제된 뒤 endpoint의 미선택 자식이 생존 앞 블록 아래로 이동

증거 한계

Notion contenteditable의 실제 pointer selection은 브라우저 자동화가 신뢰성 있게 구동하지 못했다. 이 부분은 제공된 스크린샷과 사용자 확정 규칙을 사용했다. 실제 IME 조합과 block-selection printable input도 자동화 결과를 정책 근거로 쓰지 않았다.

pointer · user confirmedIME · policy decided / implementation blocked
현재 코드는 이 표의 비-IME D1–D7 정책을 구현한다. text drag는 origin mode를 유지하고, Shift 탐색·mutation·clipboard·viewport-bounded damage가 같은 canonical selection을 사용한다. 직접 marked-text callback은 기존 overlay contract만 검증하며, 설치된 IME delivery와 live replacement lifecycle은 구현·product 검증 전이다.
