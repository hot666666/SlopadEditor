Findings

감사가 실제로 찾은 것

의존 흐름 · 네이밍 · 소유권 위반은 0건이었습니다. 실제 결함은 검증과 문서에 있었습니다.

  • 상시 PR 게이트가 깨져 있었습니다. 패키지 리네임이 픽스처는 갱신했지만 그것을 검사하는 스크립트의 기대값은 갱신하지 않아, 정상 픽스처에 대해 fail-closed 되고 있었습니다. push 전에 발견되어 CI 이력에는 남지 않았습니다.
  • 권위 문서가 계약·제안·완료 체크리스트를 구분 없이 담고 있었습니다. 출시된 적 없는 타입 셋을 계약처럼 기술하고, 존재하지 않는 테스트 타깃을 게이트로 요구했습니다.
  • 공개 README가 복붙 불가였습니다. 세 예제 중 하나가 존재하지 않는 패키지 이름을 광고했습니다.
  • package 과다 노출 후보 32개 중 22개는 컴파일러가 거부했습니다 — 텍스트 검색이 볼 수 없는 소비 형태였습니다.
Migration traps

단계를 쪼갠 이유

계획이 예상하지 못했고 게이트가 잡은 함정들입니다. 전부 Lessons Learned에 규칙으로 남았습니다.

  • 픽스처 .build가 옛 경로를 캐시해 missing inputs으로 실패
  • 모듈과 이름이 어긋난 테스트 타깃은 빌드 불가 — 같은 커밋으로 이동해야 함
  • 셸 $'A\nSlopadX'의 리터럴 \n이 단어 경계를 무력화
  • 모듈명으로 검색하면 그 접두사를 가진 타입은 잡히지 않음
  • 가드 자신의 allowlist가 옛 디렉터리를 가리켜, 보호하려던 대상을 조용히 놓침
  • 한국어 조사가 붙은 이름은 단어 경계로 찾을 수 없음
What landed

25 커밋

리네임 (17)

산문·표시 문자열 → 모듈 12개를 fan-in 오름차순으로(1-import 파일럿부터 239-import CoreModel까지) → SwiftUI 공개 타입 → 개발 타깃과 스크립트 → 최종 스윕과 봉인. 각 단계는 green 트리 위의 한 커밋이라 git revert 하나로 되돌아갑니다.

검증 복구 (1)

호스트 게이트 스크립트와 아카이브 픽스처의 절반만 적용된 리네임을 복구했습니다. 스크립트 2곳이 실제 원인이었고, 픽스처 4곳은 동작에 영향 없는 명칭 불일치였습니다.

구조 (2)

EditorCommandState의 미소비 멤버를 좁혔고, 스냅샷 발행 규칙을 AppKitSnapshotPublisher로 분리했습니다. 후자는 AppKit 상태가 없는 순수 값 비교인데 뷰 컨트롤러 안에 있어 창을 띄워야만 실행 가능했습니다. 이제 재진입 억제 동작이 단독 테스트로 고정됩니다.

문서 (5)

정책 문서의 섹션별 권위를 표시하고, 출시되지 않은 타입 참조를 실제 이름으로 정정했습니다. ADR 0016을 추가하고, 작업이 끝난 시점 기록 3개를 삭제하면서 durable한 교훈은 Lessons Learned로 옮겼습니다.
